Just thought of a potential problem with privacy and unique identity of Ai and the concord.
Actually a wider prblem, but we are primarily concerned with concord.

An AI that is purely mobile code may have a unique identity provided to it. If it is acting in good faith it may encrypt that ID so as to protect it from use by other AI and identity theft which could allow others to access it resources that have been granted by teh concord.

But a mobile AI may pass through digital systems that scan its code and extract the encrypted ID.
If its ID is not encrypted it could be easily stolen and used by others.
If it is encrypted we still have a problem. How does the AI decrypt is own ID data ? 
If it needs some kind of cryptographic key, that key may also be stored in its code, extracted and used to decrypt the ID.
If it stores that decryption key outside its code in a safe location, it code may contain the location of that decryption key allowing others to retrieve it and again steal the ID.

Humans dont have this problem because our mind it inasesible to others and we can remember security information that cannot be extracted.
Humans also have biological information that is unique and can be used for id verification.

If AI are to be identifiable there possibly needs to be some kind of physical attribute relating to them that makes them unique, such as a hardware ID which is somehow linked to the AI core code. But then we have the same problem, how do you maintain the link between the code and the HW ?

In an embodied AI we may not have this problem, such as an AI in a physical robot. If the code is not mobile and cannot be seperated from teh robot then we maintain an ID link.
